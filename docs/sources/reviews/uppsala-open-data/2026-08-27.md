## Rights and access

Uppsala municipality states that its open data may be reused and shared freely for any purpose and may be distributed, modified and built upon. It also states that municipal open data does not identify private persons or companies. The selected catalog item is public, requires neither authentication nor a contract, and exposes a queryable ArcGIS Feature Layer.

The dataset item has no separate populated `licenseInfo` or `accessInformation` value. The municipality's portal-level policy therefore remains the recorded terms basis. Display and exports should still attribute `Uppsala kommun` as a conservative provenance practice.

## Verified technical profile

The layer is a public polygon Feature Layer in EPSG:3011. Its query endpoint supports JSON, GeoJSON and PBF, pagination and ordering. `outSR=4326` returns GeoJSON polygons ready for the existing PostGIS stack. The advertised page size is 1,000 records; no service-wide request-rate limit or availability SLA was found.

Relevant fields:

| Field | Meaning | Use |
|---|---|---|
| `OBJECTID` | ArcGIS object identifier | Source-local cursor/dedupe component, not assumed permanent |
| `STYPE` | Building purpose subtype | `1001` means `Bostad` |
| `STATUS` | Current status | Includes planned, under construction, existing and demolished states |
| `MODIFICATIONDATE` | Changed timestamp | Incremental query candidate, but explicitly not a latest-inspection date |
| `ACTIVITYTYPE` | Recorded building activity | Includes approved permit, finished building, changed information and demolition |
| `Shape.STArea()` | Polygon area | Validation/context only |
| `Shape` | Polygon | Spatial matching and map display |

Observed on 2026-08-28:

- 40,827 residential (`STYPE=1001`) features;

These are a live snapshot, not contractual volumes or historical event counts.

## Semantic and operational limits

1. The layer is a current feature snapshot, not an immutable event log.
2. `ACTIVITYTYPE` must not be interpreted as a new event during the initial baseline.
3. The dataset description says `MODIFICATIONDATE` is not the latest inspection date.
4. The municipality warns that building position, size, correctness and freshness vary by area.
5. `OBJECTID` is the only exposed object identifier and is not documented as stable across republishing.
6. The layer contains no address or property-register identifier; any property association must be spatial and confidence-labelled.
7. A building change, permit or completion is contextual development evidence, not proof that a tenant or owner will move.
8. No service-wide rate limit or update SLA is published.

Because of these limits, baseline import and later diffs must be separate modes. Baseline records create no event, signal or score. Later changed records remain contextual and score-neutral until independently validated.
