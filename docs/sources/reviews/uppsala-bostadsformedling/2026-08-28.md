## Verified findings

The current public listing application is available without an account at:

- https://www.bostad.uppsala.se/mypages/app/

The rendered list exposed 307 regional listings during the review. Public cards exposed a stable numeric object identifier in the canonical detail URL plus street, municipality/region, rooms, area, rent, application deadline, move-in date, landlord and housing badges. Interest registration still requires login; reading the public inventory did not.

The public JavaScript bundle contains a GraphQL operation named `getRentalObjectsAvailable` targeting `/mypages/api`. A controlled anonymous request using that exact named query returned HTTP 200 and 307 regional objects on 2026-08-28; the adapter retained 201 objects explicitly labelled Uppsala across 18 published landlords/managers. No introspection, login or security bypass was used. The implemented query deliberately requests only the minimum lifecycle and provenance fields. Because the interface has no published integration SLA or request limit, recurring execution remains disabled by both a database source flag and an environment kill switch.

No separate published licence or terms page granting recurring automated reuse of listing data was found in the reviewed official material. Queue and mediation rules govern the housing service and applicants; they are not a data-reuse licence. This is an unresolved production condition, not a claim that reading public facts is unlawful.

## Coverage and deduplication

This source is the best first local aggregator:

- Uppsalahem states that all its available apartments are rented through Uppsala Bostadsförmedling.
- Rikshem states that Uppsala and Knivsta listings are mediated through Uppsala Bostadsförmedling.
- Victoriahem states that all its available Uppsala apartments are mediated through Uppsala Bostadsförmedling.
- Newsec states that the Uppsala homes it manages are mediated through Uppsala Bostadsförmedling and that Newsec has no own queue.
- Stena Fastigheter states that its Uppsala apartments are mainly mediated through Uppsala Bostadsförmedling; a separate internal queue exists for current Stena tenants.
- Current public cards also included landlords such as Victoriahem, Uppsalahem, Rikshem, Skandia Fastigheter and Bonnier Fastigheter Bostad.

Do not build separate Uppsalahem or Rikshem listing collectors. Preserve the displayed landlord as `upstream_provider` so multiple domains never create false independent-source confirmation.

The source does not cover the full market. A same-day listing comparison confirmed that Heimstaden's direct Uppsala page and the Bostadsförmedling's Heimstaden filter contained different current addresses. Heimstaden also states that only a limited set of Flogsta student homes is mediated through Uppsala Bostadsförmedling. HSB Uppsala has its own search and says that some homes are published only on HomeQ.

## Adapter boundary

The first adapter should normalize only public object facts:

- source object ID and canonical detail URL;
- street, municipality/region and district;
- landlord/upstream provider;
- rooms, area and rent;
- listing start, application deadline and move-in date when present;
- public housing categories/badges;
- coordinates only when the reviewed interface supplies them as object facts.

Exclude images, free text, applicant counts, queue position, eligibility criteria, accounts, applications, documents and all applicant or tenant data. Applicant count is public but volatile and unnecessary for the first lifecycle signal.

The deterministic fixture and the production-facing live adapter have separate source identities. This prevents a small fixture snapshot from ever aging live listings. The live parser filters explicitly to Uppsala, rejects malformed or duplicate identities, fails above 500 Uppsala objects and maps unknown landlords to their stable published landlord ID instead of guessing a slug.

Removal inference is independently disabled. It may only be enabled after repeated complete-snapshot observations; even then, at least two consecutive confirmed misses are required. A missing listing must never be labelled “rented”.

## Snapshot-integrity verification — 2026-08-29

The public UI displayed 290 total results. Its deployed bundle calls the parameterless
`getRentalObjectsAvailable` operation once, stores the complete returned `rentalObjects` array and
uses `numberOfItemsToReveal` only to incrementally render cards. The same anonymous operation
returned 290 objects, 290 unique numeric IDs and no GraphQL errors. Region counts were:

Rule `ubf-public-graphql-v2` therefore permits `COMPLETE` only for the explicit
`regionName=Uppsala` subset when every global object has a unique ID and non-empty region, the
filtered counts match and the cap is not reached. The first persisted v2 run recorded 189 of 189.
Missing region labels, global duplicate IDs and count mismatch become `INCOMPLETE`. An empty global
or Uppsala response still fails closed rather than authorizing a mass-removal snapshot.

## Live gate

Recurring live collection remains default-off until all of the following are true:

1. the reviewed endpoint and minimal query still match the public application;
2. a conservative polling interval and identifying client header are deliberately chosen;
3. the stored-field boundary above is preserved;
4. repeated observations confirm complete-snapshot behavior before removals are enabled;
5. live execution is explicitly enabled through both source and environment kill switches.

The existing contact draft remains usable, but it should ask for an accepted read interface and operational limits rather than asserting that public access itself is forbidden.
