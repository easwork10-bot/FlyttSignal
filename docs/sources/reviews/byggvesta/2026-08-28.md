# ByggVesta Uppsala — own queue

## Decision

- Source/interface: `byggvesta/own-queue`
- Purpose: observe direct Uppsala rental-listing lifecycle
- Decision: `WAIT`
- Access gate: authenticated applicant portal or an approved partner feed
- Signal value: `MEDIUM`
- Reviewed: 2026-08-28

Do not build a collector against an applicant account. Ask for an approved listing feed or API if this independent channel becomes important enough to operate.

## Verified findings

ByggVesta's current first-party instructions say that applicants create an account, sign in and then register interest in available apartments. The site links both `Lediga lägenheter` and `Mina sidor` to `minasidor.byggvesta.se`.

The footer also contains an older link to `marknad.byggvesta.se/pgSearchResult.aspx`. On 2026-08-28 that hostname had no DNS record and could not be treated as a current public interface. The public Kronhuset page confirms an Uppsala rental property and 132 apartments, but it is a property description rather than a vacancy feed.

This establishes an independent ByggVesta distribution route, but not a stable anonymous listing interface. No adapter or synthetic fixture is justified yet.

## Reopen gate

Reopen implementation when one of these is available:

1. a current anonymous listing page with stable object identifiers and permitted recurring use; or
2. a documented feed/API and written scope covering listing reads, retention, provenance and lifecycle updates.

An approved adapter must keep `upstream_provider_key=byggvesta`, exclude applicant/profile data, and fail closed when Uppsala scope or snapshot completeness cannot be proven.
