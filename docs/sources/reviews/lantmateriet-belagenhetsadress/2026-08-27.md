## Verified access model

- Access must be ordered while logged in to Geotorget and is assigned to an organisation account.
- The product supports Basic authentication and OAuth 2.0. OAuth 2.0 client credentials is the preferred machine-to-machine option.
- Production API: `https://api.lantmateriet.se/distribution/produkter/belagenhetsadress/v4.2`
- Verification API: `https://api-ver.lantmateriet.se/distribution/produkter/belagenhetsadress/v4.2`
- Production and verification credentials are administered separately in the API portal.
- The product is free of charge, but electronic access is subject to FRL purpose review and applicable conditions.

No authenticated product request has been made. On 2026-08-27 the Geotorget order flow reported a missing usage category; a general purpose/access question was then sent to Lantmäteriet and is awaiting response.

## Verified technical surface

The REST API serves JSON or XML. JSON is the FlyttSignal target. The official OpenAPI 3.1 specification and technical documentation describe:

- address lookup by object UUID;
- batched lookup of at most 250 address or register-unit IDs;
- nearest-address lookup by point;
- address-reference search by free text or geometry;
- address autocomplete and reference resolution;
- a health endpoint;
- `basinformation`, `berorkrets` and `total` response selections;
- GeoJSON geometry in several supported Swedish reference systems, with SWEREF 99 TM (`EPSG:3006`) as the default.

Reference searches allow at most 500 results and default to 100. A service-wide request-rate limit was not found in the reviewed public documentation and must be confirmed before a live polling schedule is set.

Address information is maintained by municipalities and changes flow through when the property register is updated. Coverage is national, though the documentation warns that addresses may be missing in some areas.

## Privacy and licence findings

Lantmäteriet states that information in the property register that can be linked to a natural person can be direct or indirect personal data; a property designation is given as an example. Access is decided from the purpose stated in the application.

The reviewed conditions require, among other things:

- processing only for the purpose approved in Lantmäteriet's decision;
- data minimisation for every selection;
- the recipient to carry its own GDPR and other legal responsibility;
- storage and processing within the EU/EEA unless the decision permits otherwise, with additional conditions for US-owned cloud services;
- acceptance that access may be audited, changed or revoked.

The data is offered under CC BY 4.0 with attribution requirements, but that licence does not override the approved-purpose and personal-data restrictions.

## Minimal FlyttSignal integration contract

The offline adapter may be implemented now from the public OpenAPI specification and examples. It must:

1. remain disabled by default behind both source enablement and `LANTMATERIET_LIVE_ENABLED=false`;
2. use OAuth 2.0 client credentials where available and keep credentials outside the repository;
3. request `basinformation,berorkrets`; retain only register-unit UUID, designation and type from `berorkrets`;
4. limit use to Uppsala address validation for already permitted property observations;
5. never search by, store or infer names, personal identity numbers or person profiles;
6. never emit events, signals or score components;
7. use small exact-address or point queries, conservative caching and a rate below the later-confirmed service limit;
8. store only fields and raw-response retention explicitly covered by the approval;
9. begin with sanitized fixtures and schema-drift tests; a controlled verification-environment run waits for legitimate credentials;
10. expose the required Lantmäteriet attribution wherever derived address data is displayed or exported.

## Implementation verification

- Implemented: 2026-08-27.
- Sanitized EPSG:3006 FeatureCollection fixture; no real person or owner data.
- Exact-current-address and Uppsala-only validation.
- OAuth 2.0 client-credentials support with secrets outside the repository.
- `basinformation` plus selected `registerenhetsreferens` fields: UUID, designation and `Fastighet`/`Samfällighet` type.
- Register-unit links are stored separately and cannot become events or signals.
- Idempotent database run verified; event and signal deltas are both zero.
- Source and live kill switch remain disabled by default.
- Signal-detail UI verified in desktop/mobile widths with explicit `Testdata`, `Verifierad livedata` and empty states.
